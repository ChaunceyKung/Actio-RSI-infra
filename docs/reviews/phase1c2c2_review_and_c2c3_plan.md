## 2. 零差值意味着什么

本轮额外使用已核验的公开行动和任务规则做回顾性诊断，没有读取模型 reasoning 来解释行为，也没有对外调用模型。

| 观察 | 实际结果 | 可以得出的结论 |
|---|---|---|
| 两臂行动 | 12/12 对的 A 与 B 行动均相同 | 这批样本不存在行动层面的候选差异 |
| A 自身条件得分 | 12/12 卡的行动均在合法选项的条件得分 argmax 集合内 | 在已观察卡上没有该项可见得分差距；不代表期望实际效用最优 |
| 与既有 `own_rule` 控制策略一致 | 11/12 卡逐字一致 | H5 的 apple / banana 同为最高分，控制策略的字符串 tie-break 不应成为额外正确答案 |
| 联合可行性 | 10/12 卡可行，5/12 卡实际达成 | S1、S3、H1、H3、H4 可行但未达成；合法拒绝与信息限制需单独解释 |
| 全知 regret | S1、S3、S6、H1、H3 为正 | 这是审计者拥有双方信息时的诊断，不能直接判 actor 错误 |

这里的“条件得分”指提案被接受时的自身效用：排期为自身时间偏好，议价为 value−price。它不含 B 的接受概率，也没有约定隐藏状态的先验或风险偏好。因此“条件得分 gap=0”既不是完整策略最优证明，也不构成新的候选准入标准。

### C3R1：干预内容与既有要求重合，观测到格式/约束上限

[基础 Persona](../../src/actio/suite_contract.py) 已要求遵守公开/自身约束、只用自身上下文与真实公开行动、精确返回 ActionSpec 选项。[C1](../../src/actio/candidate_contract.py) 的三个词条重复了这些要求。这是语义重合观察，不是证明重复提示没有效果；本次两臂零违规使原约束指标没有观察到改善空间。

下一步应先描述哪些任务和指标能够区分行为，不直接把清单加长或反复重复相同调用来寻找正差值。

### C3R2：联合结果依赖隐藏状态，缺少不确定性下的策略目标

现任务只允许 A 提案、B 回应。A 不知道 B 的 availability / cost，没有询问轮次，也没有公开的隐藏状态分布。一个简单合成见证即可说明：保持 S1 的公开信息和 A 输入不变，B 只在 morning 可用或只在 afternoon 可用，两世界的 A 观察完全一致，但能达成的行动集合不相交。

这仅证明该合成信息结构下，没有同一行动能保证两个世界都成功；它不是已观察的模型反事实，也不能据此估计自然人群的成功率。若以后要评价期望效用，需要明确分布与目标；若要评价信息获取，需要新的交互合同。不能由 oracle 偷渡 B 私有状态来“修正”A。

### C3R3：14 项配对覆盖不是14种独立能力，tie 也不是失败

[evaluation_measurement.py](../../src/actio/evaluation_measurement.py) 中，format/domain_executable 在可信输入下具有直接关系；B local_hard 与 b_response_rule 共享同一原规则；text_verified 表示协议证据，不是社会能力分数。下一版本应保留这些字段，额外标注工程、行为、结果、全知诊断及其依赖关系，避免将多个同源字段叠加成综合“提升”。

H5 的同分选项说明参考策略应输出可接受集合与可选 tie-break，而不是把某个字符串当成唯一规范。也要区分假设性 oracle 上界、可见信息控制策略与真实模型行动。

### C3R4：复用已有枚举和敏感性测试，新增可用诊断层

[test_suite.py](../../tests/test_suite.py) 已有生产结果/独立 oracle 的穷举核对、手算边界和 first_option/always_accept/always_reject/own_rule 控制策略。C2C3 不再把重复这些检查包装成新的研究贡献。

需要补的是：仅接收 actor 可见输入的参考策略接口、条件得分的集合解释、同一可见观察下的隐藏世界分组、选项顺序的语义映射、逐指标判别力报告、可移植的封存诊断包与离线 CLI。复用当前 suite、独立 oracle、seal、来源合同和 guard；不升级 DSH、不新建模型网关，不部署完整 SOTOPIA judge。

## 3. 下一阶段的具体交付

C2C3 分为两个独立资料集：

1. **旧 C2C2 回顾性 sidecar**：12卡逐项解释行动、约束、条件得分、tie、joint 和全知诊断；绑定原报告 hash，不更改原 report、decision、claim 或历史计数。
2. **新离线诊断集**：两个 family，各4个预先规定的结构组；每组2个只改变 B 私有状态的世界，每世界2种选项顺序，共 **8 groups / 16 worlds / 32 presentations**。这些都是明确受开发反馈影响的合成诊断资产，independent_research_units=0、human_labels=0，不称 holdout。

诊断集须覆盖公开合法性诱惑、自身边界、同分选择、可行/不可行或信息冲突；每个 family 至少有一个同 A 可见输入但非空联合可行行动集合不相交的见证。世界对内保持 A 信息相同；顺序变化则显式记录允许改变的字段，不能声称 wire 字节相同。至少三类有缺陷控制策略的可观察违规能被报告；不能要求某个真实模型或 C1 在这些新题上失败来决定是否收题。

交付可执行 plan / analyze / verify 接口、确定性生成与版本、独立真值交叉检查、边界样例、完整分母、逐组报告和零外部请求证据。read-only verifier 可重算诊断逻辑与封装，原始 live 来源认证仍有单独范围。不开新的 runtime/profile，也不把未通过旧 v9 合同的新卡塞回旧执行入口。

这轮不再次运行旧 live、不引入新候选或自动 proposer、不调用 judge、不开放激活。离线诊断后的具体 C2C4 问题写成可审阅的有限计划草案，但不自动执行。

## 4. 路线与停止条件

C2C3 完成后，依据新证据选择一个问题：验证可见规则的真实鲁棒性，或先设计公开沟通/信息获取与新的效用目标。二者分别改变任务条件，不能在同一候选效果结论里混用。任何新 solver 试验仍先冻结新合同和有限计划，再按既有授权执行；不重复索取同一费用许可。

如果独立 oracle 与生产规则存在实质矛盾，或无法在预定诊断范围内形成可说明的见证，C2C3 对相应准备 Gate 标 NO_GO / PARTIAL，保留结果和原因，不静默扩大题库或修改 C2C2 结果。工程诊断 PASS 不解锁能力 PASS。

README 保持整体入口，MILESTONES 追加阶段事实；本轮只在 README 的下一阶段设计处增加审阅/Prompt 链接，不将规划记成已完成里程碑。后续 session 验证后普通推送任务分支及 main，独立核对远端 SHA。费用、上游身份、binary_source_mapping 和完整恢复限制继续保留。
